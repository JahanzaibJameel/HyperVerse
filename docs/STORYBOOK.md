# Storybook

**`pre-release`** · verified `2026-09-29` · ~4 min read

Storybook for React Native (7.6.x) is wired into the project and runs on a **separate port
(8082)** so it does not interfere with the app's dev server on 8081.

> [!NOTE]
> This is a *component* Storybook, not a visual regression tool. It renders individual
> components in isolation. It does not run on CI and does not gate anything.

## 1. Running it

```bash
npm run storybook        # React Native / device
npm run storybook:web    # web, in the browser
```

Both start on port 8082. On a device, connect the device to the dev server at that port —
same as the app, just a different port.

The Storybook UI is exported from `.storybook/index.tsx`. To run it inside the app rather than
on its own dev server, replace the app entry point:

```tsx
export { default } from './.storybook';
```

and run `npm run dev` as normal. To switch back, restore the original entry point. The
Storybook config and stories live in `.storybook/` either way.

## 2. Layout

```
.storybook/
├── main.ts              Storybook config: stories glob and addons
├── preview.tsx          Preview-level parameters
├── index.tsx            Exports the Storybook UI root
├── storybook.requires.ts  Auto-generated by metro.config.js; do not edit
└── stories/
    └── components/
        ├── CircularProgress.stories.tsx
        ├── GlowCard.stories.tsx
        ├── GradientCard.stories.tsx
        ├── LiveTicker.stories.tsx
        ├── MiniBarChart.stories.tsx
        ├── NeonButton.stories.tsx
        ├── NotificationBadge.stories.tsx
        ├── ShaderBackground.stories.tsx
        ├── SkeletonLoader.stories.tsx
        ├── StatBar.stories.tsx
        └── XPBar.stories.tsx
```

`storybook.requires.ts` is generated by `metro.config.js` from the `stories` glob in
`main.ts`. It is regenerated on every Metro run, so the story index always matches the files
on disk. It is excluded from ESLint because it is machine-generated.

## 3. Writing stories

```tsx
import { View, Text } from 'react-native';
import type { Meta } from '@storybook/react';
import { GlowCard } from '@/components/GlowCard';

const meta = {
  title: 'Components/GlowCard',
  component: GlowCard,
  args: { children: 'Card body text' },
} satisfies Meta<typeof GlowCard>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {
  args: { glowColor: '#00e5ff', intensity: 'medium' },
};
```

Rules:

- One file per component. `title` controls the sidebar grouping; the component name is the
  story name.
- Use `args` for the default state and per-story overrides for variants. Avoid passing
  `style` or callbacks directly — they are not serialisable across the device bridge.
- Stories are linted and typechecked like the rest of the codebase, so a broken import fails
  `tsc` and `eslint`, not just Storybook.

## 4. How it is wired

- `metro.config.js` sets `transformer.unstable_allowRequireContext: true` and calls the
  Storybook `generate()` script, which produces `storybook.requires.ts` from the stories
  glob. Generation is wrapped in try/catch so a broken glob cannot break the app build.
- `main.ts` declares the stories glob and the on-device addons
  (`@storybook/addon-ondevice-controls`, `@storybook/addon-ondevice-actions`).
- `index.tsx` calls `view.getStorybookUI({ storage })`, where `storage` is backed by
  AsyncStorage so addon state persists between runs.

## 5. Limitations

- **On-device only.** This is the React Native Storybook, which runs on a device or
  simulator. It does not produce a web-only book like `@storybook/react`.
- **No controls for non-serialisable props.** `onPress` and callbacks cannot be edited in the
  controls panel; pass them as `args` with a no-op and assert behaviour in tests instead.
- **Not in CI.** There is no Storybook workflow, so stories are only verified by running
  Storybook locally. They are still typechecked and linted.
- **Peer warnings.** `@storybook/react` and `@sentry/react` declare peer ranges that do not
  include React 19. They install and resolve, but `pnpm install` reports unmet peers. This is
  advisory only and does not affect the build.

## 6. What these stories revealed

Writing stories for every component is a cheap way to find bugs that unit tests miss, because
you render the component with real props in a real tree. Three issues surfaced here:

- **`MiniBarChart` hard-codes SVG gradient IDs** (`barGradActive`, `barGradInactive`). Two
  charts on one screen would share an ID, and the second one's stops would override the first.
  Each chart needs its own ID derived from a counter or a prop.
- **`CircularProgress` derives its gradient ID from `label`** (`grad_<label>`). Two progress
  rings with the same label — say two "Steps" rings in a grid — would collide the same way.
- **`SkeletonLoader` mixes `useNativeDriver` settings** inside one animation. The first timing
  uses `Platform.OS !== "web"`, the second hard-codes `true`. On web the first leg runs on the
  JS thread, so the shimmer stutters.

None of these break the app in normal use, which is exactly why they were invisible to the
test suite. They are tracked in [ROADMAP_V2](ROADMAP_V2.md#3-duplication-and-drift) rather
than fixed here, because fixing them is a behaviour change and needs a decision about what the
right behaviour is.
